# Releasing a preview

Developer previews are distributed from immutable Git tags. Applications pin
that tag as `vendor/wabou`, so Rust and TypeScript come from the same revision.
Publication to npm and crates.io is deferred.

## Release Please

Release Please maintains one repository-wide version. Its manifest starts at
`0.1.0-alpha.4`; the next release is `0.1.0-alpha.5`. Conventional Commits on
`main` update a release PR with the root changelog, Cargo workspace version,
root package version, and all six TypeScript package versions. The workflow
refreshes Cargo and Bun lockfiles on that PR branch. CLI scaffolding derives
its default tag from the Cargo package version.

Review the release PR and wait for CI before merging it. Merging is the explicit
release decision: Release Please then creates the immutable `v…` tag and GitHub
prerelease. It does not merge PRs. The workflow dispatches tag validation with the full native behavior,
layout, and Linux packaging jobs. Check that run before recommending the tag.
Installation examples pinned to older previews remain valid; update them when
promoting a newer preview in the documentation.

Do not run a separate version preparation script or move an existing tag.
Do not edit `.release-please-manifest.json` for ordinary releases.

## Repository setup

Use the built-in `GITHUB_TOKEN`; no PAT or additional secret is required.
Enable **Allow GitHub Actions to create and approve pull requests** under
Settings → Actions → General → Workflow permissions. Release Please creates
and updates PRs; maintainers review and merge them.

The workflow explicitly dispatches `ci.yml` on the release PR branch after
refreshing lockfiles, and on the tag after creating a release. Both dispatches
run the full validation suite. This avoids relying on events generated by the
built-in token: tag pushes do not trigger workflows, while bot-created PR runs
can require approval. Explicit `workflow_dispatch` events run normally with
`GITHUB_TOKEN`. See the
[GitHub token documentation](https://docs.github.com/en/actions/concepts/security/github_token).

## Validation

Before merging a release PR:

```bash
bun install --frozen-lockfile
bun run verify
```

Inspect Gallery captures at 1× and 2× and smoke-test `wabou new` against the
candidate revision. Stale generated output must be regenerated and reviewed on
the PR branch. Future npm/crates publication can be attached to Release Please's
`release_created` output after the package boundaries stabilize.
